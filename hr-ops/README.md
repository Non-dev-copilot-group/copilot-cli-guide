# HR / Ops — GitHub Copilot CLI 실무 시나리오

> **채용 이력서 처리, 사내 문서 폴더 관리, 온보딩 체크리스트 자동 생성** 등 HR·운영 실무에서 반복되는 업무를 CLI 로 처리하는 3가지 시나리오.

이 폴더는 [메인 가이드](../README.md) 의 HR / Ops 편입니다. **설치·인증·안전 수칙은 [메인 문서](../README.md)를 먼저 읽어주세요** (특히 [8번 안전 수칙](../README.md#8-반드시-알아야-할-안전-수칙) — 이력서 등 개인정보를 다루므로 특별한 주의 필요).

## 각 시나리오 읽는 법

- **상황** — 어떤 문제인가
- **프롬프트** — 그대로 복사해서 붙여넣을 수 있는 한국어 명령
- **결과** — 무엇을 받게 되는가
- **팁** — 반복 사용 / 안전 팁

**전제**: 아래 예시들은 모두 대화형 모드(`copilot`) 안에서 입력합니다. **개인정보가 포함된 파일은 반드시 회사 정책 확인 후 사용**하세요.

## 시나리오 A. 이력서 PDF 50개에서 필드 추출

**상황**: 채용 공고에 지원한 이력서 50개 PDF. 이름·연락처·경력 년수·이전 회사·주요 스킬을 표로 정리해야 함.

**프롬프트**:
```
./resumes/ 폴더의 모든 이력서 PDF 를 읽어서 아래 컬럼으로 candidates.csv 를 만들어줘:

- 파일명
- 이름
- 이메일 / 전화
- 총 경력 년수 (숫자, 없으면 빈칸)
- 최근 회사 3곳 (콤마 구분)
- 주요 기술/툴 (콤마 구분, 상위 5개)
- 언어 능력 (한/영/기타)
- 신뢰도 (high/medium/low)

low 신뢰도는 파일명에 [REVIEW] 태그를 붙여서 검토 대상임을 표시.
개인정보 유출 방지 위해 이 CSV 는 ./resumes/ 폴더 안에만 저장하고 다른 곳으로 옮기지 마.
```

**팁**: **개인정보 파일** 은 반드시 회사 정책을 먼저 확인하고, 필요 시 `/sandbox enable` 로 네트워크 접근을 차단한 상태에서 실행하세요. 결과 CSV 도 접근 권한이 제한된 폴더에 두세요.

## 시나리오 B. 사내 문서 폴더 구조 리네이밍

**상황**: 사내 공유 드라이브의 폴더/파일명이 뒤죽박죽. 표준 규칙에 맞게 일괄 리네이밍.

**프롬프트**:
```
이 폴더 아래 모든 하위 폴더와 파일을 아래 규칙으로 리네이밍하는 계획을 먼저 표로 보여줘.
실제 변경은 내가 확인한 다음에 진행.

규칙:
- 폴더명: [연도]_[분기]_[프로젝트명] 형식 (예: 2026_Q3_OKR)
- 파일명: [연도-월-일]_[문서유형]_[제목].[확장자]
  - 문서유형: MEMO / REPORT / MINUTES / DRAFT
- 공백은 _ 로 대체, 한글은 그대로 유지
- 원본 이름을 매핑 파일 rename_map.csv 에 남길 것

실제 리네이밍은 rename_map.csv 를 내가 검토한 뒤에 진행하고,
실행 후에 되돌리기 가능한 undo_rename.sh 스크립트도 만들어줘.
```

**팁**: **"undo 스크립트" 를 함께 요청** 하는 게 핵심입니다. 대량 리네이밍 사고 방지. 실제 리네이밍 전에 `rename_map.csv` 를 열어서 몇 건 랜덤 샘플링해 확인하세요.

## 시나리오 C. 신입사원 온보딩 체크리스트 자동 생성

**상황**: 신규 입사자 5명분 온보딩 체크리스트를 각자 맞춤형으로 만들어야 함.

**프롬프트**:
```
new_hires.csv (컬럼: name, team, role, start_date, mentor) 기준으로,
onboarding_template.md 를 참고해서 각 신입사원별 개인 체크리스트를
./onboarding/{start_date}_{name}.md 로 생성해줘.

각 파일은:
- Day 1, Week 1, Month 1, Month 3 섹션으로 구성
- 팀별로 필요한 툴 설치 항목 다르게 (marketing 팀: Adobe / GA / Mixpanel, sales 팀: Salesforce / Gong, engineering 팀: GitHub / Jira / IDE 등)
- 담당 멘토 이름과 첫 1:1 스케줄 (start_date + 3일) 자동 채움
- 마지막에 "1개월 회고 회의" 캘린더 초대 초안도 포함
```

**팁**: 팀별 툴 목록을 별도 `team_tools.md` 파일로 만들어 폴더에 두면, Copilot 이 자동으로 참조합니다. 조직도가 바뀌면 그 파일만 업데이트하면 됨.

## HR / Ops 실무자 추천 프롬프트 패턴

1. **개인정보 파일은 로컬 샌드박스 필수** — `/sandbox enable` 로 네트워크 접근 차단
2. **결과 파일 저장 위치를 명시적으로 제한** — "이 폴더 안에만 저장하고 다른 곳으로 옮기지 마"
3. **대량 리네이밍/삭제는 반드시 undo 스크립트 병행** — 사고 발생 시 즉시 복구 가능
4. **AI 추출 결과에는 신뢰도 컬럼** — 검토 대상 자동 표시 (`[REVIEW]` 태그 등)
5. **팀·부서별 참조 문서를 폴더에 함께 배치** — 조직도, 툴 리스트, 정책 문서 등을 Copilot 이 참조하게
6. **개인정보가 든 결과물은 회사 정책에 맞는 접근권한 폴더로만** — 클라우드 동기화 폴더 주의
