# HR / Ops — Ch 2. 활용 (중급)

> **난이도**: 중급 ★★☆ | **소요 시간**: 30분 | **선수 학습**: [Ch 1. 사용법](./ch1-basics.md) 완료

Ch 1 에서 파일에 "말 걸기" 를 배웠다면, 이 챕터는 **폴더 리네이밍, 온보딩 체크리스트 자동 생성, 정책 문서 통합 요약** 같은 **HR · Ops 반복 잡업의 자동화** 를 다룹니다.

> **주의**: 이 챕터는 사내 문서와 개인정보를 다룹니다. 반드시 [메인 README 8장 안전 수칙](../README.md#8-반드시-알아야-할-안전-수칙) 확인 후 진행하세요.

---

## 이 챕터에서 배우는 것

- 사내 문서 폴더를 **표준 규칙에 맞게 일괄 리네이밍** (undo 스크립트 병행)
- 신입 5명의 **팀별 맞춤형 온보딩 체크리스트** 자동 생성
- 여러 정책 문서를 **한 페이지 요약** 으로 통합

## 이 챕터의 핵심 패턴

HR · Ops 자동화는 **되돌리기 어려운 파일 조작** 이 많습니다. 아래 3가지 습관을:

1. **대량 리네이밍 · 삭제 전에 undo 스크립트 병행 요청**
2. **개인정보 파일은 로컬 샌드박스** 에서 (`/sandbox enable`)
3. **결과 파일 저장 위치를 프롬프트에 명시적으로 제한** ("이 폴더 안에만")

## 예시 1. 사내 문서 폴더 구조 리네이밍 (undo 스크립트 포함)

**상황**: 사내 공유 드라이브의 폴더/파일명이 뒤죽박죽 (`문서.docx`, `report_final_final2.pdf`, `무제-2.md`). 표준 규칙에 맞게 일괄 리네이밍해야 함.

**폴더 준비**:
```
~/work/docs-cleanup/
  2025년 4분기 회고.docx
  report_final_final2.pdf
  주간회의 - 카피 (2).md
  ...(뒤죽박죽한 파일 여러 개)
```

**프롬프트**:
```
이 폴더 아래 모든 하위 폴더와 파일을 아래 규칙으로 리네이밍할 계획을 표로 먼저 보여줘.
실제 변경은 내가 계획을 검토한 다음에 진행.

리네이밍 규칙:
- 폴더명: [연도]_[분기]_[프로젝트명] 형식 (예: 2026_Q3_OKR)
- 파일명: [연도-월-일]_[문서유형]_[제목].[확장자]
  - 문서유형 자동 판별: MEMO / REPORT / MINUTES / DRAFT (파일 내용 참고)
  - 판별 어려우면 DOC 로 표기
- 공백은 _ 로 대체, 한글은 그대로 유지
- "카피 (2)", "final_final" 같은 노이즈는 제거

산출물:
1. rename_plan.csv (변경 전 -> 변경 후 매핑, 문서유형 판별 사유 포함)
2. 실행 후 rename_map.csv (실제 실행된 매핑)
3. undo_rename.sh (또는 undo_rename.ps1 for Windows) — 실행 전 상태로 되돌리는 스크립트

절차:
1. rename_plan.csv 만 먼저 만들고 파일 20건 요약을 화면에 표시
2. 내가 "진행해줘" 라고 하면 실제 리네이밍 실행 + undo 스크립트 생성
3. 완료 후 rename_map.csv 로 최종 로그 저장
```

**예상 결과**:
- Step 1: `rename_plan.csv` 만 생성. 실제 파일은 그대로.
- Step 2 (승인 후): 실제 리네이밍 + `rename_map.csv` + `undo_rename.sh`
- 실수했으면 `bash undo_rename.sh` 로 원복 가능

**팁**:
- **`rename_plan.csv` 는 반드시 열어서 검토** 하세요. 20건 이상이면 랜덤 샘플링 5건은 눈으로 확인.
- **undo 스크립트가 실제로 동작하는지 시험** 해보세요. 파일 하나로 원복 테스트.

## 예시 2. 신입사원 5명 온보딩 체크리스트 자동 생성

**상황**: 이번 달 입사자 5명. 각자 소속 팀과 역할이 달라서 온보딩 체크리스트도 개인화해야 함.

**폴더 준비**:
```
~/work/onboarding-202608/
  new_hires.csv            (컬럼: name, team, role, start_date, mentor, laptop_type)
  onboarding_template.md   (기본 체크리스트 템플릿)
  team_tools.md            (팀별 필요 툴 정리, marketing / sales / engineering / etc.)
```

**프롬프트**:
```
new_hires.csv 기준으로 각 신입사원별 개인 체크리스트를 만들어줘.
onboarding_template.md 와 team_tools.md 를 참고.

출력 경로: ./onboarding/{start_date}_{name}.md
- start_date 는 YYYY-MM-DD 형식
- 예: 2026-08-05_홍길동.md

각 파일 구조:
1. 헤더: 이름, 팀, 역할, 입사일, 담당 멘토
2. Day 1 (입사 당일)
   - 사무실 안내, 계정 발급, 랩탑 세팅 (laptop_type 반영)
3. Week 1 (첫 주)
   - 팀별 필요 툴 설치 (team_tools.md 참고)
   - 팀 미팅 참석, 멘토 1:1 (입사일 + 3영업일)
4. Month 1 (한 달)
   - 팀 리뷰, 첫 프로젝트 배정, 사내 필수 교육
5. Month 3 (수습 종료)
   - 수습 평가 회의, 정직원 전환 절차

각 항목마다 완료 체크박스 - [ ] 를 넣고, 담당 부서(HR/IT/팀장/멘토) 를 표기.

마지막에 onboarding/README.md 로 5명 리스트와 각 파일 링크 요약.
onboarding/schedule.csv 로 5명의 주요 일정 (Day 1 / Week 1 미팅 / Month 1 리뷰 등) 통합 스케줄 저장.

먼저 1명 시연 → 확인 후 나머지 4명 진행.
```

**예상 결과**:
- `onboarding/` 아래 5개 개인 체크리스트 md
- `onboarding/README.md` 총괄 인덱스
- `onboarding/schedule.csv` 5명 통합 일정 (엑셀에 붙여넣기 좋음)

**팁**:
- **팀별 툴 목록을 `team_tools.md` 로 별도 관리** 하면 조직 변경 시 그 파일만 업데이트하면 됨.
- 멘토 1:1 스케줄은 실제 캘린더 초대장까지 만들지는 않지만, **"각 멘토에게 보낼 캘린더 초대 초안도 함께 만들어줘"** 로 확장 가능.

## 예시 3. 사내 정책 문서 5개 → 한 페이지 요약

**상황**: 신입 온보딩 자료 준비 중. 사내 정책 문서 5개(휴가, 근태, 재택, 경비, 보안)를 신입에게 한 페이지로 소개할 요약 자료가 필요.

**폴더 준비**:
```
~/work/policy-onboarding/
  policies/
    01_holiday.md          (휴가 정책)
    02_attendance.md       (근태 정책)
    03_remote_work.md      (재택 정책)
    04_expense.md          (경비 정책)
    05_security.md         (보안 정책)
```

**프롬프트**:
```
./policies/ 폴더의 정책 문서 5개를 읽어서 신입사원용 한 페이지 요약을 만들어줘.
결과 파일: onboarding_policy_summary.md

구조:
1. 헤더: "우리 회사 5분 정책 가이드"
2. 각 정책마다:
   - 아이콘 없이 굵은 제목 (예: **휴가**)
   - 3줄 이내 핵심 규칙
   - 신입이 자주 헷갈리는 포인트 (1~2개, "주의" 로 표기)
   - 원문 링크 (파일 경로)
3. 최하단: FAQ 5개 (신입이 첫 달에 자주 묻는 질문 예상)
4. 최하단2: "더 궁금하면" 섹션 (담당 부서 이메일 · 슬랙 채널)

톤: 담백하고 친근. 사내 용어는 괄호 안에 짧게 설명.
길이: 신입이 5분 안에 다 읽을 수 있는 분량 (A4 1~2장).

정책 원문에 있는 예외 조항이나 자주 놓치는 부분을 "주의" 로 강조해줘.
```

**예상 결과**: `onboarding_policy_summary.md` 파일이 생성되어 신입 온보딩 슬라이드 · Notion 페이지 · 이메일에 바로 붙여넣기 가능.

**팁**:
- **원본 정책 문서가 업데이트 되면 이 프롬프트를 재실행** 하면 요약도 자동 갱신.
- **"FAQ 5개는 실제 신입이 자주 물어본 질문을 반영"** 하려면 예전 슬랙 로그를 폴더에 함께 두면 더 정확해집니다.
