# Sales — GitHub Copilot CLI 실무 시나리오

> **리드 리스트 정규화, 견적서 대량 생성, 계약서 검토, TAM 분석, 콜드 아웃리치 개인화** 등 세일즈 실무에서 반복되는 업무를 CLI 로 처리하는 5가지 시나리오.

이 폴더는 [메인 가이드](../README.md) 의 Sales 편입니다. **설치·인증·안전 수칙은 [메인 문서](../README.md)를 먼저 읽어주세요** (특히 [8번 안전 수칙](../README.md#8-반드시-알아야-할-안전-수칙) — 고객 데이터를 다루므로 개인정보 보호 정책 확인 필수).

---

## 각 시나리오 읽는 법

- **상황** — 어떤 문제인가
- **프롬프트** — 그대로 복사해서 붙여넣을 수 있는 한국어 명령
- **결과** — 무엇을 받게 되는가
- **팁** — 반복 사용 / 안전 팁

**전제**: 아래 예시들은 모두 대화형 모드(`copilot`) 안에서 입력합니다. **고객 데이터가 든 CSV/PDF 를 다루므로 반드시 회사 정책을 먼저 확인**하고, 필요 시 `/sandbox enable` 로 네트워크 접근을 제한하세요.

## 시나리오 A. Salesforce/HubSpot Export 리드 리스트 정규화

**상황**: CRM 에서 뽑은 1,000건 리드 CSV. 회사명 표기가 뒤죽박죽 ("삼성전자" / "Samsung Electronics" / "삼성전자(주)"), 지역명이 통일 안 됨.

**프롬프트**:
```
crm_leads_202607.csv 를 정규화해줘:

1. company_name 컬럼: 한글 정식명으로 통일 (예: "Samsung Electronics" -> "삼성전자", "(주)" 제거)
2. region 컬럼: 서울/경기/인천/부산/그 외 로 정리 (도로명 주소 참고)
3. industry 컬럼이 비어있으면 회사명 기반으로 추정 값 채우기 (자신 없으면 "미확인")
4. 이메일 도메인이 무료 (gmail, naver 등) 인 건은 lead_type = "personal", 나머지는 "corporate"
5. 정규화 전/후 값이 바뀐 필드는 별도 change_log.csv 로 저장 (수동 검토용)

결과는 crm_leads_normalized.csv.
```

**팁**: `change_log.csv` 를 만들어두면 정규화가 잘못된 케이스를 나중에 확인 가능합니다. **자동화 결과에는 항상 검증 파일을 함께 만드는 습관** 을 프롬프트에 넣으세요.

## 시나리오 B. 견적서 30건 자동 생성 (엑셀 템플릿 채우기)

**상황**: 견적서 템플릿(`quote_template.xlsx`) 하나가 있고, 고객별 데이터(`clients.csv`) 로 30건을 만들어야 함.

**프롬프트**:
```
quote_template.xlsx 를 템플릿으로, clients.csv 의 각 행을 채워서
30개의 견적서 파일을 ./quotes/ 폴더에 만들어줘.

파일명: quote_{client_id}_{client_name}_{YYYYMMDD}.xlsx

템플릿 안의 아래 셀을 clients.csv 값으로 치환:
- {{CLIENT_NAME}} -> client_name
- {{CONTACT_EMAIL}} -> email
- {{AMOUNT}} -> amount (콤마 구분자, 원)
- {{VALID_UNTIL}} -> today + 30 days (YYYY-MM-DD)

먼저 1건만 미리 만들어서 결과 보여준 다음, 확인받고 나머지 진행해줘.
```

**팁**: "**먼저 1건만 만들어서 보여주고 확인받고 나머지 진행**" 이 매우 안전한 패턴입니다. 처음 몇 번은 항상 이렇게 하세요.

## 시나리오 C. 계약서 PDF 20건에서 특정 조항 추출

**상황**: 지난해 체결된 계약서 20건 PDF 에서 "**갱신 자동 연장 조항**" 이 있는지 확인해야 함.

**프롬프트**:
```
./contracts/ 폴더의 모든 PDF 를 읽어서, "자동 갱신" 또는
"자동 연장" 관련 조항이 있는지 확인해줘.

결과를 auto_renewal_check.csv 로 만들어줘. 컬럼:
- 파일명
- 조항 유무 (Y/N)
- 조항이 있다면 원문 (해당 문장 그대로)
- 조항이 있다면 페이지 번호
- 신뢰도 (high/medium/low, 판단 근거도 짧게)

low 신뢰도 건은 반드시 사람이 재확인해야 한다고 요약에 언급해줘.
```

**팁**: **AI 판단에는 항상 "신뢰도" 컬럼을 요청** 하세요. 100% 는 없습니다. 계약 검토 결과는 반드시 법무팀 크로스체크가 필요합니다.

## 시나리오 D. 지역별 잠재 TAM 산정 자료 정리

**상황**: 신규 진출 검토 중인 6개 도시의 인구·산업체 수·경쟁사 수 를 자료 5개에서 뽑아 하나로 정리.

**프롬프트**:
```
./tam_research/ 폴더에 있는 통계청 xlsx, KOSIS csv, 시장조사 pdf 5개 문서를
읽어서 서울/부산/대구/인천/광주/대전 6개 도시별로 아래 항목을 표 하나로 정리해줘.

- 인구 수
- 잠재 산업체 수 (자료 기준 명시)
- 경쟁사 매장 수 (자료 3의 표 4 참고)
- 우리 서비스 TAM 추정치 (=산업체 수 * 평균 계약 단가 500만원)
- 데이터 소스 파일명과 페이지

결과를 tam_summary.md 로 저장.
```

**팁**: **"데이터 소스 파일명과 페이지" 를 반드시 요청** 하세요. 나중에 임원 질문이 들어왔을 때 근거 추적이 가능합니다.

## 시나리오 E. 콜드 아웃리치 메일 30건 개인화

**상황**: 잠재 고객 리스트(`prospects.csv`)를 기반으로 각자 맞춤형 인트로 문장을 넣은 이메일 초안 30개 필요.

**프롬프트**:
```
prospects.csv (컬럼: name, company, industry, recent_news) 를 기반으로
각 잠재 고객에게 보낼 이메일 초안을 outreach/{name}_{company}.md 형태로 생성해줘.

각 이메일 규칙:
- 인사말은 이름 + 직함 (직함 정보 없으면 "님")
- 첫 문장은 recent_news 를 참조한 자연스러운 관심 표현 (1문장)
- 두 번째 문단: 우리 회사 소개 (product_pitch.md 참고, 3~4줄)
- 마지막: 15분 통화 제안 + calendly 링크 (https://cal.com/example)

톤은 정중하지만 딱딱하지 않게. 각 메일 최대 200자 이내.
발송 전 사람이 반드시 검토해야 한다는 주석을 파일 최상단에 넣어줘.
```

**팁**: **"발송 전 사람이 반드시 검토" 주석** 같은 안전장치를 프롬프트에 명시하세요. 자동화된 결과물은 항상 사람이 확인하는 게 원칙입니다.

## Sales 실무자 추천 프롬프트 패턴

1. **원본 데이터는 절대 덮어쓰지 말 것** — 항상 새 파일로 저장 (`_normalized.csv`, `_cleaned.csv` 등)
2. **`change_log.csv` 부산물 요청** — 정규화·변환의 전/후 값 추적용
3. **`신뢰도` 컬럼 요청** — 계약서 조항 추출, 리드 스코어링 등 AI 판단이 개입하는 모든 결과물에
4. **1건 시연 → 확인 → 나머지** 패턴 — 대량 생성 작업의 사고 방지
5. **개인정보 관련 파일은 로컬 샌드박스** — `/sandbox enable` 로 네트워크 전송 최소화
6. **금액·날짜 포맷을 프롬프트에 명시** — 원 표기, 콤마 구분, YYYY-MM-DD 형식 등
7. **자동 발송/제출 금지** — 이메일·계약서·견적서는 반드시 사람이 최종 확인
